# 六设备同步与升级说明（0.8.0）

适用：3 台电脑和 3 台 Android 手机，同一数据账号使用相同的坚果云用户名和同步目录。账号 A 与账号 B 继续使用不同目录。每台设备首次打开时生成独立设备标识，不需要手动填写设备编号。

## 如何保证同一周期内各设备的变化都能补齐

同步使用每台设备独立递增的批次号。例如清单记录电脑 1 到第 12 批、电脑 2 到第 8 批、手机 1 到第 21 批；某设备本地只读到 10、8、19，就需要补电脑 1 的 11–12 批和手机 1 的 20–21 批。

- 变更先与任务一起写入本地 SQLite 事务中的发件箱，断电或退出后仍存在。
- 上传不可变批次文件，成功后再用 ETag 条件写更新小型清单。竞争失败时重新读取最新清单，仅合入本设备进度，不覆盖其他设备。
- 下载按每个来源设备的连续批次补齐。遇到缺失、损坏或网络错误，不跳过该批次。
- 记录修改和已读进度写入同一个 SQLite 事务；重复收到批次可安全重放。
- 同步完成表示“已补齐本次最后读取的清单中的全部变化”。之后才提交的变化会在下次检查补齐；离线或后台暂停的手机需要恢复前台联网后接续。

每台设备的批次文件位于所选坚果云目录的 v2/ 下，小清单为 v2/manifest.json。首轮可能分多个回合；界面会显示仍需继续同步，不把部分完成报成全部完成。

## 并发编辑与删除

使用逻辑版本与因果关系，不用设备时钟的新旧直接决定胜负。不同字段可以分别保留；同一字段真正并发的版本保留在数据库中，在“设置 → 坚果云同步 → 查看并处理同步冲突”选择采用的内容。选择会作为新变更同步。

删除保留删除标记。离线设备的旧副本不会自动使已删除记录复活；有删除冲突时可以明确选择保留。数据库保留冲突版本和删除记录，因此长期离线后仍能正确合并。并发更换父任务形成循环或父任务已删除时，相关子任务会作为根任务显示，以保持可访问。

同一电脑的标签页共享一个设备标识；保存不同字段会合并，同一设备先后保存同一字段采用后一次保存。不同设备并发同字段则保留冲突。一个本地数据库同一时间只允许一个同步会话，其他窗口仍可保存，发件箱会接续发送。异常退出后同步租约最多约 2 分钟自动失效。

## 手机资源与流量

- SQLite 原生事务和索引；仅更新变化的记录。提醒只查询未完成且设置了提醒的记录；桌面组件只读取各象限前三条及数量。
- 增量文件和快照采用 gzip。没有新变化时通过条件 GET 检查小清单，304 不下载任务内容。
- 连续编辑合并约 15 秒后上传，并尊重撤销时间；不会每输入一个字就发起网络请求。
- 仅在前台自动同步，打开或回到前台约 2 秒后检查；空闲前台约 5 分钟检查一次并加入少量随机间隔。
- 后台或离线暂停，已在途的单个请求可以收尾；不设同步唤醒闹钟、常驻服务或同步唤醒锁。原有任务提醒仍由系统闹钟负责。
- 失败后指数退避，最长约 30 分钟；每个收发阶段最多 12 批，推送后还可能再执行一个拉取阶段，快照分片另计；继续回合约 10 秒后触发。
- 任务列表和时间轴分批渲染。当前前端仍会载入账号的完整业务数据，尚未实现全部页面的数据库分页查询；大规模数据在低内存手机上的开销仍需注意。

## 快照与恢复

首次完成同步，以及之后累计约 64 个批次时，在前台空闲且发件箱已清空的条件下生成分片快照。快照包含字段版本、删除标记和各来源批次位置；每个分片都有 SHA-256 校验。

新设备或落后较多的设备可合并快照，再补后续批次；其本地尚未上传的内容会保留。快照只在所有分片上传完成后登记到清单。当前保留旧快照和历史批次，不自动清理云文件；本机已确认上传的发件箱条目会删除。

JSON 导出仍是可读的业务数据备份，不含同步密码及内部版本历史。完整设备备份应在停止服务或退出应用后保存该账号目录，包括 SQLite 相关文件。不要把正在使用的 tasks.sqlite 放进坚果云客户端自动同步目录，也不要把同一活动数据库直接复制到另一台设备运行；新设备安装程序后通过应用同步加入。

## 从 0.7.0 升级

1. 在全部电脑和手机安装 0.8.0。Android 使用同一签名，可直接覆盖安装。
2. 首次打开账号将旧 state.json 原子导入 tasks.sqlite，原 JSON 保持原样作为升级前备份。
3. 保留各账号原有坚果云配置，首次新版同步会把旧云端 state.json 保存为 v2/legacy-随机编号.json.gz，再写入旧版拒绝读取的升级标记，然后启用增量协议。
4. 依次打开六台设备对应账号完成首轮同步，再检查任务数量及冲突列表。

旧版应用在目录升级后无法继续同步；其本地编辑仍在，可以先导出备份再升级。请勿让旧版回写已迁移的本地目录。程序会拒绝旧网页的整份状态写入，刷新页面即可使用新版入口。

电脑需要 Node.js 22.13 或更新版本。当前电脑保留 M:/dev/gxtodo-local/data；其他没有旧数据目录的 Windows 电脑默认使用 %LOCALAPPDATA%/GxTodoLocal/data。可用 GXTODO_DATA_DIR 指定位置。每个账号分别拥有 tasks.sqlite，账号清单与凭据继续独立存放。

## 本轮验证范围

包含六端交错提交、清单竞争、断线重试、缺失批次、快照校验、离线删除、同字段冲突、同机同步会话互斥、切换云目录、旧协议迁移、SQLite 事务回滚和压缩传输测试。真实坚果云六客户端联调已通过，实际观察到条件写竞争的 412、空闲 304 和压缩批次的正常收发；没有实测六台实体设备的长期耗电。模拟器和其他 IDE 的可复用测试方法见 [Android 测试指南](android-testing.md)。
