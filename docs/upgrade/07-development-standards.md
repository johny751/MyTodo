## 3. 数据与迁移合同

保留 `meta/entities/outbox`、原稳定ID、字段因果合并、冲突版本、墓碑及本地事务/CAS语义。SQL schema、复制格式、业务备份、账号清单和派生搜索版本分别登记；`updatedAt`不能代替因果版本。未知历史时间明确未记录/null及来源，不用迁移时间编造原创建时间。

新业务kind/字段同时审核共享model/replica、Windows C、Android存储桥、序列化、导入导出和快照；不能只加SQL列或只改JS白名单。业务行data、record、事件、序号/outbox和业务历史按统一事务写入；远端重放不重新生成业务事件/outbox。现有会裁剪的record和已ACK删除的outbox不能当永久历史。

任何schema升级按09执行：覆盖全部账号与所有写入口的停写门槛 → 一致备份及清单 → 校验可恢复副本 → 事务DDL/回填/迁移登记checksum → 校验 → COMMIT → 完成记录。备份失败、未知schema、SQL/磁盘失败必须保全原数据并停止。COMMIT与外部标记间崩溃依据数据库迁移登记恢复，不盲目覆盖已提交库；外层迁移事务不能直接嵌套现有自行BEGIN的业务入口。

备份保全actor、seq、clock、vector、cursors、scope/epoch、pending、outbox、冲突/墓碑，以及新增批次、目标义务、收据和会话状态。活动WAL库不能只copy一个.sqlite文件。跨设备业务导入不得克隆副本身份或待发布批次；凭据保留平台保护边界，备份清单不能包含明文密码/密钥。

具体DDL、内部事务单元、协议能力和新旧映射由主Agent实现前内部审核。审核是工程集成门槛，不是再次询问用户产品需求；未实现或未执行验证的方案不能描述为已支持。

## 4. 统一批次、目标投递与ACK账本

详细行为以03“正式同步规范”为准，以下不变量在所有平台生效：

1. 同一事件组在首次发送前持久冻结一个逻辑 `batchId`，独立于LAN/WebDAV及会话。逻辑空间、来源、事件身份/范围与内容校验值不可变；同身份异内容必须拒绝。保留原 `actor + seq` 事件身份，以持久映射接既有WebDAV v2文件/manifest，不重写历史批次。
2. 发送端以同一事务登记批次和所需目标集合；每个 `(workspaceId, batchId, targetId)` 有独立持久投递/ACK状态和可恢复重发内容。连接地址、session或凭据不是目标身份，actor也不等于硬件设备身份。来源vector与接收游标不等于目标投递完成。
3. LAN ACK仅确认该认证目标持久接收；WebDAV ACK仅确认共同云空间可靠发布。LAN ACK不能删除待WebDAV义务，WebDAV ACK不能影响其他目标。ACK验证空间、目标、批次及内容，重复确认幂等；任何旧全局outbox删除路径不得旁路账本。
4. 只有所需目标全部完成，且批次/收据/快照/墓碑/历史保留条件同时满足，才可逻辑GC。未完成义务必须一直有发送端本机持久保存的完整、不可变、可校验载荷。物理outbox行只能在新本机副本写入并校验、引用安全切换后释放，崩溃后至少一份有效副本可读；远端WebDAV路径、内存缓存或不能重建原批次的实体快照不能替代，LAN补发不得依赖联网回取坚果云。恢复时载荷缺失/哈希错误须保留义务并明确报错，不能读成空批次或确认成功。超时、设备撤销、设置切换不自动等于ACK；目标义务终止采用明确持久管理策略。
5. 同 `batchId` 跨通道接收共用持久去重收据，事件仍以原身份及因果状态去重。身份相同但内容不同拒绝，不覆盖既有收据；重复接收返回原ACK，不重复应用、生成业务历史事件或回灌outbox。
6. 接收端完整校验后，在同一事务提交实体/冲突/墓碑、vector/clock、合法连续来源游标和接收收据，COMMIT成功才ACK。无效/缺批次或SQL失败不得半批提交、提前推进游标。快照逐片幂等，所有片完成才确认整体进度。
7. 批次冻结后发送前、接收COMMIT后ACK前、发送端收到ACK后账本提交前、WebDAVmanifest发布后本地确认前，均从持久批次/收据/云证据恢复同一身份。租约/会话世代防止过期发送者更新新进度；失败、重启或切通道不能清空其他目标队列。

payload、delivery、receipt、session的最终表名/索引和接口签名在内部审核时固定；上述不变量已决定，不能等实现时临时改成单通道全局ACK。

## 5. 三端协议与同步验收

共同JSON夹具须覆盖Windows C实际实现、共享JS实际实现与Android Java真实SQLite/生产桥适配。至少让每个平台生成样本、另两个实际接收并导出，再比较同一规范化实体、字段版本、冲突/墓碑、vector/cursors、outbox、目标账本和持久收据；重开库后再核对恢复状态。Java计时单测、内存对象或另写的模拟合并算法不能证明Java同步适配通过。

| 必测向量 | 验收结果 |
|---|---|
| A/a、ASCII标点、Unicode/编码长度、安全整数、key/context边界 | 三实现采用同一校验/排序合同；无效输入整批拒绝，事务/游标不变；现有合法身份兼容 |
| 重复、乱序、缺中间批次、冲突、墓碑与快照片段 | 实际投影/版本收敛，连续进度不跳过，删除不被迟到数据复活 |
| 同批LAN先ACK/WebDAV待ACK及反向顺序 | 仅对应目标终态变化，另一目标和唯一重发内容仍存在 |
| WebDAV已ACK、LAN待投递，载荷迁移后重启且广域网不可用 | 从本机持久副本校验并发送同一batchId，无坚果云请求；载荷迁移各崩溃断点不丢副本，缺失/损坏不误判为空或提前ACK |
| 同批两通道并发、重复ACK、错目标/错hash/旧会话ACK | 一次逻辑应用，幂等目标确认，错误ACK不改变账本或业务状态 |
| SQL/磁盘/事务故障、COMMIT前后及ACK丢失、强制退出重开库 | 明确失败或依持久收据恢复，无提前ACK/游标、无丢义务/重复业务事件 |
| WebDAV发布断点、旧v1备份/fence恢复、目录/目标切换 | 原数据保全、同批恢复；不初始化空云，不清另一通道队列 |
| GC、快照/墓碑/收据保留 | 未完成目标不能失去可重发内容，完成后仍满足保留门槛；迟到/重复接收保持幂等 |

共享逻辑、同步、数据和迁移有变更时，其相关JS回归始终必跑，正式Web UI全量重构暂缓不构成跳过理由。Windows C自测不包含HTTP互通，mock fetch不包含真实坚果云，Android模拟器SQLite不证明真实Wi-Fi/mDNS/后台行为；结果必须分别报告。T01–T16沿用08映射，未覆盖项保留，不将相同wire、源码推导或历史README记录写成“互操作已通过”。
