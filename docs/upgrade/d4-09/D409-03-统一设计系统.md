# MyTodo D4-09 统一设计系统

设计版本 1，2026-11-28。业务基线 7c217d8779ccf21e13733b28868e015e9cfd693a。用户已授权原型后自主 UI 实施，生产准入未授权。

## 产品方向：让每项工作有清楚的下一步

MyTodo 同时服务个人任务、项目和流程执行。视觉以清晰的工作台、可扫描的工作队列、随选随看的详情为中心。避免把桌面工作管理做成大型手机卡片，也避免在每个区域堆叠仪表数字。

特征元素是“工作脉络”：列表中的项目色标、流程阶段与下一步行动在详情侧栏连续对应；番茄页把当前事项和计时轨道放在一起。色条表达真实归属和状态，不作装饰。Windows 采用固定导航、紧凑工具条、主从分栏；Android 以单列层次和可触达底部主要动作为主；Web 用宽布局的列表/详情和上下文栏。

初稿自评：仅改默认控件颜色不能解决 Windows 的导航横排、表单堆叠和番茄空白。最终方向需要重排区域、明确当前选择、把编辑动作与记录阅读分开。仅保留工作脉络这一个显著视觉元素，取消无业务意义的大号编号和装饰图形。

| canvas | #F2F6F8 | 应用背景 |

辅助：边框 #D8E2E8，选中浅色 #E4F1F5，危险 #B64343，警告 #936015，成功 #277348，信息 #256B9E。四象限沿用紧急/重要语义；红、金、青、绿仅作边框/小面积标签，正文保持深色。状态始终同时使用文字或图标，不能仅凭颜色。选择文字使用深蓝背景/白字，保留浏览器和原生选取能力。

## 字体与密度

标题：Windows Segoe UI Variable Display（回退 Segoe UI / 微软雅黑），Android sans-serif-medium，Web Segoe UI Variable Display / 本地 Noto Sans SC。正文：Windows Segoe UI / 微软雅黑，Android sans-serif，Web Segoe UI / Noto Sans SC。数字/计时：Windows Bahnschrift / Consolas，Android sans-serif-light 并使用 tabular numbers，Web Bahnschrift / ui-monospace。使用已在工程或系统内的字体，不增加运行时下载依赖。

字号：桌面标题 24–28，分组 16–18，正文 14，辅助 12；Android 标题 24，正文 16，辅助 13–14。计时数字桌面 64–80，手机 56–64；数字视觉与正文分工，避免以超大计时压缩动作区。

间距使用 4/8/12/16/24/32。桌面页面边距 24（窄窗16），列表行40–44，输入34–36；手机边距16，触摸目标至少48dp，列表最小56dp。桌面圆角6/8，手机12/16；卡片轻边框，弹窗使用克制阴影，主布局不用卡片套卡片。

## 页面结构

Windows：导航宽196–216，工作区标题+一个主动作，过滤条，左侧列表与右侧详情；宽度不足1000时详情切换为明确返回的面板；番茄页左专注工作区、右历史与概览。可缩放，保持系统标题栏和窗口行为。

Android：顶部标题+明确菜单入口，正文纵向布局，当前页动作固定或贴近内容。任务选择为搜索弹层；父项显示未完成子项数，默认折叠，搜索命中子项时自动显示其父链与命中子项。切换筛选不改变底层任务关系。

Web：左导航+宽主区+可选详情栏，工作台用当日待处理队列和项目进展，表格适合批量扫描，详情展示完整正文。≤960折合详情，≤640进入单列；手机360/412仍可操作。

## 状态与交互

- 页面切换保留当前页面查询、选中项与滚动；未保存编辑必须有保存/放弃选择，不能静默丢弃。
- 新建在当前上下文进入编辑，保存成功显示“已保存”，失败保留草稿和明确重试入口。当前存储若仅内存，继续显示既有持久化警告。
- 删除保留现有二次确认；原业务依赖/保护检查优先，不能为了新交互绕过。
- 空态说明缺少什么并提供真实可用的主动作；加载和错误不得伪造成功。按钮须真实响应，原型中的演示行为须标明为合成数据。
- 菜单用真实 button/menu，Esc关闭，焦点返回触发点；Tab顺序清楚，焦点外环2px+2px间距。Ctrl+Enter保留，Enter不误触危险动作。
- 四象限拖动、跨象限、三点菜单、自动完成、子任务、放大等全部保留。
- Android 系统返回保留优先权；不使用全屏手势排除。菜单按钮始终可用；边缘横滑只在有效内容区、非编辑/拖动/弹窗、横向意图明确时识别，避开系统边缘返回保留区，竖向滚动不触发。精确 dp 和 insets 由原生适配文档及云端手势/三键矩阵确定。
- 尊重系统减弱动画：只使用120–180ms状态过渡，计时不依赖动画或页面刷新。UI不是计时和持久化的权威来源。

## 实施保全合同

所有变化必须是视觉、布局、导航、输入选择和必要的UI层重构。业务模型、Schema、SQLite路径、计时内核、生命周期服务、备份校验/恢复、ACK/outbox/cursor/manifest/batch完全沿用基线。演示数据只存在独立原型内存，不写产品存储。

设计原型的浏览器绘制不是 Win32 或 Android 原生运行证明。原生候选分别由原平台代码构建并测试，交付中分开标注。原D4-08测试字节冻结；D4-09另增独立视觉/新交互检查。
