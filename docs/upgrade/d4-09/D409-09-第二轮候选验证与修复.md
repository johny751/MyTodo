## 已定位的剩余问题

1. **Win32 多行表单 Tab**：原输入轨迹在描述 Edit 4804 连续停留。D409 呈现开关下为多行控件增加对话框 Tab/Shift+Tab 处理，并保留 IME 状态与 Return 输入；原收集/保存业务不改。新驱动记录全部焦点路径，反向焦点也必须断言。
2. **Windows 日期菜单驱动**：第二轮真实菜单落在第三项“月”。新驱动按实际新菜单的选择起点操作，并在 Enter 前保存菜单原图；仍同时要求 Combo 索引 3 和“全部日期”标题，不直接改控件值。
3. **新备份 fixture 的日期保真**：PowerShell JSON 自动把时间字符串末尾零规范化。96 下原事项 `.590Z` 变 `.59Z`；144 下项目也有同类变化。原导入按“同时间不同内容，双方保留”产生冲突副本，业务逻辑正确。只修独立驱动为 `DateKind String`，并对六类集合的原记录、数量、唯一 ID 和双向覆盖加断言，不改导入/统计/冲突逻辑。
4. **Android 新任务层级用例**：四组合 U03 均在 expanded child 超时。原图与输入日志显示 Dialog 可见框的根坐标被误作屏幕坐标，原生 tap 偏移约为 Dialog 原点；修独立 D409 驱动的屏幕坐标转换并保留实际可见框/位置证据。
5. **Android 三按钮系统返回定位**：两宽度 U05/06/07/08 均未定位到系统返回按钮。原窗口日志显示导航栏由 NexusLauncher 的 Taskbar 托管，旧驱动只接受 SystemUI 包；原档案缺 accessibility 节点树，不编造具体节点 ID。新驱动须核对真实系统窗口、底部导航区域、可见节点和已观察 owner，保存查找诊断并继续 MotionEvent 点击，不得用 keyevent 回退。
6. **指定页面截图补齐**：U04 原本访问 13 路由但仅保存 3 路由截图。下一候选让全部访问页面各留原图，并逐 phase 校验 13 个文件及 U04 归属；仍是 8×4=32 项，不把新增截图数算作新增测试数。
