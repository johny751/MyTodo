## N409-15 导出形状断言错误

第三轮两缩放下，原始 `task-export-30.json` 和 `task-export-31.json` 均保留六个唯一任务。真实 SendInput 操作只将 `d409-native-task-0` 从象限 0 移到 1，顺序 0 变为 2048；全部导出祖先关系和其他字段保持。

原 `windows/database.c` 导出时用 `tasks/subtasks` 表达父子关系，明确删除内部 `parentId`。新增测试错误地直接读 `parentId`，在 StrictMode 下报字段不存在。本轮只修新测试：递归还原完整祖先链、验证唯一 ID 和集合双向一致、每个祖先链一致，并仅允许唯一移动任务的 `quadrant/order` 改变。旧测试及产品导出逻辑不改；不声称直接读取内部数据库父字段。

## 旧拖动异常的独立诊断

第三轮 D404 与前两轮 D404 可执行文件 `.text` 均为 961,024 字节、SHA256 `0456aacaa5774e598fe4a3ba1090490106f6c2281d2b1d99c417457313ac27a1`，其他多数 PE 节也相同。第三轮唯一产品变更在 D409 表单，D404 容器不编译该表单。此证据不支持将异常归因于新 Tab 修复，也不证明旧异常已经修复。

新增独立 `tests/d4-09/windows/legacy-drag-diagnostics.ps1`，只在 GitHub Actions Windows 执行。原九套及原 runner 保持不变；其后固定五次执行完整原拖动套件，每次使用新的隔离合成目录，必须完整出现 101 checks / 0 failures 才算该次通过。不会重试到成功，也不会修改历史原件。

诊断临时配置同一云 runner 上此 EXE 专用的 WER LocalDumps 三项值，先备份再恢复。收集原 stdout/stderr、退出码、原始 Application/WER 事件、存在时的 dump 和哈希。没有额外安装调试器或下载符号。WER 可能不产出 dump，原优化 EXE 没有源码符号；不承诺能生成可解析的调用栈。即使五次通过，也只表示未在这五次重现，原一次 AV 仍列入历史及未决问题。

该独立诊断的合成数据目录含点前缀候选标记，上传步骤明确包含隐藏文件，使云端 SHA256SUMS 与实际 ZIP 成员完整对应；没有放宽证据审计或启用其他目录的隐藏文件上传。

## Android 两项剩余失败的证据

第三轮原件的 159 张 PNG 均核对了 hash、大小和 IHDR；U04 四组合各 13 路由共 52 图齐全。三按钮导航保留唯一实际 NexusLauncher 系统节点、受理的 MotionEvent 和前后截图，不用按键回退替代触摸。

360 手势 U02 的失败图显示目标输入 `37` 实际得到 `325`。新增驱动原先在点击输入框后直接 Ctrl+A、删除、输入，没有分别观察焦点、IME 就绪、全选与清空。后续修正采用真实按键和只读条件观察，不调用 setText 或 setSelection，不重试到成功。

412 手势 U08 的原 logcat 记录 Quickstep 收到上划后选择 `LAST_TASK` 并返回应用；不能解释为仅失焦观察过早。原输入日志的尾段三个 move 挤在同一毫秒，绝对时间补赶调度压缩了末段。后续调整仅限新驱动的单次 Home 真实手势节奏与路径，保留实际受理时间及系统窗口证据，不使用 Home keyevent 回退。修正成效必须以新 SHA 完整云端回归证明。

第四轮输入驱动先观察原生焦点、输入连接、IME 与稳定位置，再分别执行一次 Ctrl+A、删除、输入，并逐阶段核对选择范围、空文本和目标文本，失败也保存观测记录。Home 只执行一次 18 个 move 的真实上划，每次实际发送返回后再间隔 16ms，终点为屏高 22%；原失焦和系统前景窗口断言保持，没有第二次输入或回退路径。

## Android 计时按钮下缘裁切

第三轮原图局部与触摸目标收据共同显示：横向按钮测量高度至少 48dp，但实际可见高度只有 44px；开始按钮不受影响。横向行使用 CENTER_VERTICAL，按钮只有 8dp 顶边距、没有底边距，居中布局将下缘推到行外。仅给横向按钮补相同底边距，保持控件 ID、动作、启用条件和计时业务；不改阴影动画来掩盖几何问题。新 U01 增加滚入可见区域后的完整局部矩形和至少 48dp 可见高度断言，仍为四组合 32 项，下一轮另复核相同暂停计时截图。
