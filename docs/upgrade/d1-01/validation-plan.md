# D1-01 隔离合成验证计划

日期为 2026-11-24（Asia/Shanghai）。本批规划以阶段 0 审查发布提交 `d9e58b04484ce14a1bfc3021757b2167df2b0407` 为锚点，实际 `master` 身份及与阶段 0 受审源码的对应关系见 [基线核查](baseline-verification.md)。本文件列出预计验证范围，当前全部为 **NOT TESTED**。后续以经内部审查的业务、版本、备份和同步契约作为断言来源，再实现隔离夹具。

## 执行环境与隔离

- 使用全新 GitHub Actions 托管 runner，独立工作流预定为 `.github/workflows/d1-01-contract-validation.yml`。首次执行走该工作流配置的窄范围触发入口，记录准确 `GITHUB_SHA`、run ID、attempt、job 和已解析依赖。动作触发或 runner 不可用时按 BLOCKED 记录。预计利用阶段 0 已覆盖的 Node 22（使用 `node:sqlite` 前先核实具体版本 API）、Windows 构建工具和 JDK。任何新增依赖先核查当前项目联网授权。
- 被测对象是放在 `tests/d1-01/` 的合成验证器、固定向量和测试入口。数据只在该 run 的 job 专用 `RUNNER_TEMP` 子目录、进程内逻辑时钟和内存传输夹具中产生。所有文件入口先验证测试标记、真实路径和预期 DB 标识，拒绝符号链接、越界路径、预存 DB 和生产账号路径。生产入口、配置、分发资源和现有数据库不参与。checkout 步骤尽量禁用持久凭据，验证进程使用最小环境，测试运行阶段无需网络、用户凭据或任何 WebDAV/LAN 地址。
- 语义验证使用纯函数或进程内协议模型。迁移、备份、双目标账本与会话持久化的重启断言使用独立 SQLite 数据库。C/Java/JS 序列化用同一批公开合成向量，每端在各自进程以实际解析、重序列化或明确拒绝生成输出，比较规范投影、UTF-8 长度、整数值与排序。Java 使用宿主 JDK 的独立夹具，Android 真实存储、WebView 与 ADB 均不在本矩阵内。若 runner 没有满足契约的 JSON 解析设施，将对应跨语言路径标为 BLOCKED，不能用三次 JS 结果冒充三端。账本/备份的单引擎 SQLite 执行结果不外推到三端生产存储。
- 对要求进程退出的用例，由父进程接收确定性阶段标记后触发退出并记录 PID、状态、关闭边界和退出时间。随后以不同 PID 打开原测试路径，核对 DB ID、actor、scope、epoch 和全套持久状态。备份恢复写入另一个测试路径时，先明确旧库与候选副本身份，再校验恢复副本携带预期逻辑身份；用例不得把新建空库重试算作原库恢复。进程退出不能代替断电、真实设备 fsync 或生产 SQLite 封装验收。
- 文件哈希用于完整性与内容关联。备份清单的信任及会话身份授权是单独的设计约束，匹配哈希不代表来源授权。

## 预计矩阵

基础计划为 **83 个命名用例**。A 15、B 14、C 11、D 14、E 9、F 10、G 10。一个命名用例可包含多个输入边界和多宿主子执行。命名用例、运行次数、断言数和跨端比较数分列，三个宿主执行同一向量不叠加为三个不同业务场景。结果按运行实际计量。

### A. 基础业务与类型契约（15）

| ID | 场景和关键断言 |
| --- | --- |
| A01 | 合法实体。读取包含必需字段、业务数据、扩展及稳定引用的合成实体，比较各宿主的规范投影和序列化回读。 |
| A02 | 逐项省略必填字段，返回明确拒绝及字段路径；无落盘、事件或 ACK。 |
| A03 | 比较允许的 `null`、非法 `null` 与缺省。断言三种输入按字段合同区分，原值或默认值均可核查。 |
| A04 | 空字符串和缺省分开验证。允许清空的业务字段回读原空字符串，拒绝空实体 ID 和不允许为空的字段。 |
| A05 | 可扩展字段完整保留，旧端只在可无损输出且协议允许时更新；可能丢字段时阻断写入。 |
| A06 | 未知实体保留原始输入或以可审计理由隔离，禁止以忽略方式推进受其影响的连续游标。 |
| A07 | 字符串、数组、布尔和数值互换作为反例，拒绝隐式强制转换和类型不符的引用。 |
| A08 | 无效 ID 载荷包含 NUL、空值和无效编码。拒绝后实体、发件箱和游标不变。 |
| A09 | 以 ASCII、多字节、四字节 Unicode 分别构造 800 与 801 UTF-8 字节的 ID，核对接受及拒绝边界。 |
| A10 | 校验独立代理项、合法补充平面字符、组合字符和等显不同码点序列。往返保真，无静默正规化。 |
| A11 | 检查零、负数、分数、`2^53−1` 和越界值。正安全整数位拒绝零，非负计数位允许零，禁止截断和绕回。 |
| A12 | 校验契约规定的时间表示、时区、历法与解析往返。非法日期拒绝，旧数据缺少历史时间时维持未知。 |
| A13 | 关联实体不存在时依据关系类型拒绝或记录为未解析，保留稳定引用，不凭空创建或删除实体。 |
| A14 | 同类型、ID 的重复实体不得生成重复行；相同内容重放与异内容冲突分别核验；不同类型同 ID 按契约识别。 |
| A15 | 重复 actor/seq 与同一内容幂等。相同身份、不同内容发出不可重复应用的明确错误，保留前状态。 |

### D. SQLite 备份及恢复（14）

| ID | 场景和关键断言 |
| --- | --- |
| D01 | 正常备份生成正式清单和可验证 SQLite 副本；核对 DB ID、schema/contract、账号、actor、scope/epoch、行、历史、墓碑、未完任务、附件清单。 |
| D02 | 保持 WAL 活跃并写入已提交标记，以 SQLite 一致备份方式读取。副本包含受快照可见的已提交内容，排除未提交写入。记录 WAL 存在和新连接的数据库检查。 |
| D03 | 备份生成过程中真实中断子进程。重启看到上一份完整备份或明确未完成的临时副本，未完成状态不能覆盖既有完成标记。 |
| D04 | 读取清单后重算 DB、状态及内容摘要。破坏单个字节时拒绝；摘要不提供来源授权。 |
| D05 | 丢失合成附件。清单比对识别准确对象及版本，禁止把不齐的备份标记为完整。 |
| D06 | 内容长度或 SHA-256 不匹配。拒绝完成和替换既有有效附件。 |
| D07 | 恢复检查原逻辑 DB ID、schema/contract、scope/epoch，区分同设备恢复与新设备加入。actor 退役、恢复副本和当前设备冲突应阻断上线。 |
| D08 | Outbox 恢复后逐行核对稳定身份、队列序号、JSON 内容和两个目标的待投递状态。 |
| D09 | Cursor 按目标、方向和 actor 对比。恢复不能盲目清零或向后推进，落后旧备份须进入受控对账。 |
| D10 | Manifest 规范身份、heads、epoch 和远端读回证明一并核对；已变更或无法确认时阻断自动发布。 |
| D11 | Pending Batch 以原字节、hash、batch ID、seq/through、目标和 outbox 范围绑定，比对恢复前后及第一次重试的载荷。 |
| D12 | 恢复后通过内存传输模型重投重复 batch/event，比较幂等结果，不二次产生业务变更或误删未投递数据。 |
| D13 | 新 PID 打开指定的恢复副本。与原快照比较 DB ID、actor、数据、墓碑、版本与投递状态，保留原库和路径差异。 |
| D14 | 故障发生在候选验证或替换边界，原库的预先留存 hash 与持久状态可验证，重新打开可读，无清空/静默重建。 |

### F. 会话过期与迟到响应（10）

| ID | 场景和关键断言 |
| --- | --- |
| F01 | 未过期的旧会话正常完成，持久化与远端模型中的有效 CAS 均成功。 |
| F02 | 推进可控时钟使租约过期，尚未建立新会话时也拒绝旧 token 写入。 |
| F03 | 新会话增加持久 fencing 身份。对 scope、epoch、pending 绑定、存储版本和 token 作同一原子检查。 |
| F04 | 延迟 ACK 在新会话持有 pending 后到达。旧响应不能清任何队列或更新新确认水位。 |
| F05 | 延迟 batch 到达后验证本地应用受栅栏保护。模拟服务中的已写不可变对象若存在，只能在新会话验证后采用；同身份异正文拒绝。 |
| F06 | 延迟 cursor 提交不能回退或提前推进新会话游标，也不能从坏分片之后跳过。 |
| F07 | 延迟 manifest 分开验证旧响应引起的本地提交和已在途请求的远端条件写。旧响应本地拒绝；在具备远端会话栅栏或新 ETag 的模型中拒绝过期写，保留只靠本地栅栏不能阻止在途远端副作用的限制。 |
| F08 | 迟到 cache 写入不能覆盖新会话的新缓存前像；缓存前后字节和作用域绑定可比较。 |
| F09 | 两会话之间真实进程退出并重开指定账本。核对持久 token/generation、epoch、pending 和新进程 PID。 |
| F10 | 确定性排列多个迟到操作及 scope/epoch 切换，比较新会话规范状态与没有旧回调时的对照，要求一致。 |

Windows 生产代码是否有等效事务内栅栏以及现有 WebDAV 远端如何隔离在途 PUT 是独立开放风险，F 组只验证明确建模的前提和状态变换。[阶段 0 同步安全审查](../phase0-final-review/sync-safety-review.md)

### G. 保持 C0-03/C0-04 协议规则（10）

| ID | 场景和关键断言 |
| --- | --- |
| G01 | Actor 1–80 ASCII 字母数字或连字符，区分大小写，禁止空、超长及非法标点。 |
| G02 | 同事件集合在随机排列下比较逻辑时钟、ASCII actor 字节、seq 升序，跨宿主比较并发胜出、候选与墓碑投影；UTF-8 字段排序独立检查。 |
| G03 | 实体键解码为两元素数组，旧合法 kind/ID、UTF-8 长度与 NUL/Unicode 标量规则保持；合法旧键原字节输入不做正规化。 |
| G04 | 安全整数与编号耗尽。按 C0-04 区分 seq/clock/index/through 的正值和头/游标的非负值，越界不建立新 batch，保留 outbox。 |
| G05 | Actor 映射上限使用 256/257 实际边界输入。Manifest head/cursor 负数、分数、溢出及错误结构拒绝。 |
| G06 | 同一 Actor 的 snapshot cursor 不超过 manifest head，epoch 或快照身份错误在读取分片前拒绝。 |
| G07 | 注入批次中间一项错误，证明应用事务原子性及 cursor 不推进。 |
| G08 | 分片之一缺失或摘要错误时保留旧 cursor。允许已合并分片幂等重放，全部通过才推进。 |
| G09 | Pending 正文和原编号重试。匹配正文复用已有对象，不同正文拒绝覆盖，错误路径或 through 拒绝。 |
| G10 | 校验缺批或乱序接收时不越过连续水位，合法历史 batch/snapshot 的规范投影按归档黄金向量比对。 |

## CI 与回执

1. 从固定 manifest 加载 83 个计划 ID 及其必需子执行，输出每个用例的 fixture 版本/摘要、seed、宿主、SQLite/JDK/编译工具身份、阶段、断言路径、期望、观测、数据库身份及 stdout/stderr 索引。生成 JSON 和 Markdown 报告，区分设计检查和实际合成执行。代数/边界测试记录 seed、实际样本数及最小失败输入。
2. 状态以 PASS / FAIL / SKIPPED / BLOCKED 分计。预期拒绝被正确观察可算该负例 PASS；意外退出是 FAIL 或可证实的 BLOCKED。对每个本应执行的项目记录原因。强制核算 `计划用例 = PASS + FAIL + SKIPPED + BLOCKED`，另记录实到断言与实际逻辑执行数。首崩、超时、重试及预定进程中断分别记载。偶发失败后若另发 run，两次结果均保留，当前 run 不因重试改判为 PASS。
3. 验证器在输出失败记录后返回非零。必需用例失败、缺失、未执行或证据不全必须使汇总 gate 非成功。上传日志、机器报告、Markdown、隔离 fixture、选定数据快照以及逐件 SHA-256 清单的步骤在失败时也运行，不能改写验证步骤的退出结果。外层归档如使用 GitHub artifact digest，单列该摘要、生成时机与可下载的 archive 原字节重算，不以 Markdown 截图代替。
4. 计划日志目录按 commit/run/attempt/job 隔离，保存第一次失败、后续尝试及各自输入、exit、before/after hash 或语义比较。清单记录件名、字节数、SHA-256。对成功或失败都输出 run URL、工作流、job、报告/产物 URL、时间时区及真实退出码。没有执行结果的本批只交付计划，不生成通过回执。以最终真实 Actions 运行和独立证据核验申请 D1-01 验收。
