## 审计结论

1. Windows工作区隐藏在三点菜单和Ctrl+Shift+W，只有tasks/projects/notes适配。流程、往来说明页不能满足实际操作；完全缺失原生番茄钟。不是用户使用错误程序，也不能把Edge App作为补齐方案。
2. Android有唯一原生计时权威、原子存储、服务和通知，但当前页面以验证为中心，无完整原生任务选择，历史截为10条。原正式AndroidToolsActivity未注册于D405；直接复用它的旧timer会生成第二计时权威，因此应复用交互、接同一NativeTimerStore。
3. FeedbackKit原AAR及完整工具入口仍存在。原图实际字节、数据库、草稿、删除批次、恢复代次均有静态证据；不能误报功能库被删。问题是主导航呈现简化合成页，完整原流程主次不明及当前回归不全。
4. Web反馈已有真实图片内容，但缺内联预览、分类、单图移除、完整删除恢复。保存失败路径会先关闭表单，domain可能永久放弃localStorage，必须用故障注入验证草稿不丢及实际重试落盘。
5. 共享导航x≤22与Android22dp×200dp排除区过窄。旧测试固定(3,150)，不能代表全部高度/模式/编辑页面。不能通过关闭系统Back解决；应扩大应用内安全带并验证系统手势协调和控件不抢占。
6. D4-06服务适配存在但未挂页面。五个服务测试通过不代表UI操作已到正式服务；本轮只能通过新候选组合层显式注入隔离存储，正式src和真实远端仍冻结。

## 明确冲突及裁决

旧Windows测试要求任务标题Ctrl+Enter不保存，而本轮明确要求任务编辑Ctrl+Enter保存。没有足够历史证据称原任务已经支持保存。D408作为新候选合同：子任务输入焦点优先添加；其余任务编辑Ctrl+Enter保存；IME合成不提交；普通Enter/Shift+Enter保持多行输入；独立便签已有Ctrl+Enter保存保持。新宏实现并新增独立测试；旧D404构建及旧断言原文继续执行，不改旧结果。子任务原业务若先建立父记录，须说明这是关联先决条件，不能同时提交未确认的父编辑草稿或关闭父窗。

原Android计时是全设备单活跃会话，关联含accountId与taskId。三端候选沿用单活跃语义、明确账号身份与历史快照，不改成每账号并行，也不让Web/原生各起一套计时器。历史记录时间使用UTC，日期分摊Asia/Shanghai。任务改名或删除不得抹除历史关联。

原反馈是本地保存/处理/备份，未发现正式远程提交服务；本轮测试本地IO失败、权限、容量、校验和重试。未接入远程提交必须如实标为受接口/生产准入限制，禁止虚构联网成功。
