# C0-04 协议规则

本决策依据既有 [同步协议](../sync-v2.md)、[实施指南](../webdav-sync-implementation-guide.md) 和 [C0-03 实测](protocol-compatibility.md)。指南以逻辑时钟、actor 和序号决定并发字段的优先版本，并保留所有并发候选。收发以已提交的连续批次位置为准。规则适用于 Windows C、共享 JavaScript 和运行共享模块的 Android WebView。

| 项目 | 统一规则 |
| --- | --- |
| actor | 1 至 80 个 ASCII 字母、数字或短横线。身份区分大小写。保持既有身份和云文件名称。 |
| 并发排序 | 按逻辑时钟、actor 的 ASCII 字节字典序、事件序号升序。比较独立于区域设置。并发字段显示排序最后的值，保留候选。墓碑继续采用因果覆盖及并发删除优先。 |
| 冲突展示 | 冲突字段名按 UTF-8 字节序，候选按事件顺序去重。标题在所有字段投影完成后取第一个非空字符串 title、name、body，最后回退到实体 ID。 |
| 实体键及 ID | 键为 JSON 字符串，解码后是恰好两项的数组。第一项为已知 kind，第二项为非空 ID。ID 最多 800 个 UTF-8 字节，包含完整 Unicode 标量并排除 NUL。保留字符串内容、大小写、规范化形式和既有键字节。 |
| 数值 | 事件 seq、clock、批次 index、pending.through 为正安全整数。context、vector、heads 和 cursors 的值为非负安全整数。上限为 2^53−1。Windows 用 64 位表示索引和构造批次路径。编号耗尽时保留待发数据并停止创建批次。 |
| 结构 | 事件、values、context 与计数表使用 JSON 对象。上下文和清单 heads 最多 256 个 actor。清单为 v2，epoch 为非空 Unicode 字符串。快照游标必须为有效计数且不能超过同 actor 的清单 head。 |
| 验证和事务 | 批次在单事务内应用。非法快照元信息在取分片前拒绝。逐片提交仍允许重试，游标在全部分片验证成功后推进。历史 pending 的路径、编号、正文标识和计数在发布前校验，正文原样重试。 |

800 字节覆盖旧 Windows 合法 ID 的范围，也覆盖旧 JavaScript 的 200 UTF-16 代码单元范围。旧 Web/Android 业务投影原有限制更短，共享实体 ID 校验同步采用上述范围，以便已接受的 Windows 实体仍能打开。ASCII 大小写作为历史身份的一部分，不能折叠。UUID、键格式、SQLite 表、批次名、协议版本和已存在正数索引的含义保持兼容。

升级后，合法历史批次和快照继续读取。实体记录的事件排序与冲突展示在后续正常合并重算时收敛，原始历史表行和不可变批次不进行批量覆盖。有效 pending 使用原字节和原编号，已保留的 outbox 不因升级被清除。历史数据库如果已由旧缺陷写入负数 pending 或越界 cursor，保留文件和发件箱并报告错误。恢复前备份数据库与云清单，核对不可变批次与原始 outbox，再从可信备份或新副本逐批验证。没有证据时不猜测游标、不清除 pending。旧 WebDAV v1 转换和完整 SQL/ACK 故障恢复分别跟踪为 C0-06 与 C0-07。
