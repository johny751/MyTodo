## 本轮静态交叉审核与修订

**FACT（source05 静态）**：`run-browser.mjs` 的拖动驱动改为先滚入元素，再同次读取源和目标坐标，检查端点在 viewport；按下后的截图不再等待 toast。此前“目标滚动后源坐标过期”和额外 3.3 秒等待的问题已有具体调整。

**UNVERIFIED / BLOCKER**：驱动尚未验证 `elementFromPoint` 实际命中目标；被遮罩或祖先滚动裁剪的端点可能虽然在 viewport 内仍不可操作。`holdScroll` 底点尚未夹到可见区域。需云端长列表样本、命中检查、落点/原值比较与录屏；不能用 count 不变单独证明排序正确。

**FACT（source05 后静态修订）**：本子包修正分类“清除”按钮先取消该表单脏标记，防旧未提交搜索草稿被 root 页面恢复重新填入；时间轴恢复原 100 项显示批次与继续加载，筛选/周期/分类变更重置批次；分组操作先核验项目 ID/分类仍存在，项目重命名使用该 ID 当前名称，删除 ID 不回退同名项目。

**BLOCKER（root 接入待统一）**：source05 的四象限项目筛选先按 `group.name`，再只比较 `projectId`，与时间轴/工作模块的“明确 ID / 唯一名称”规则不一致。唯一名称且无 ID 的历史任务会在时间轴出现、在四象限缺失；明确 ID 而原名称字符串过时的任务也可能被先行排除。root 应共用 `DemoLegacyPages.groupTasks` 的归属规则，再对原根任务调用 `visibleTasks`，不能自行重绑数据。

**BLOCKER（root 接入待统一）**：source05 的菜单上/下排序未纳入标签/地点分组过滤；目录隐藏项仍可能使“下移”后的可见顺序不变。`openTaskGroup` 导航会恢复旧 tasks 编辑弹窗，显式进入分类四象限可能被该弹窗遮住；应保留草稿到 page memory，但消耗明确新入口时关闭旧展示弹窗。重命名/删除分类后的 root 分组和历史页面记忆也需同步更新，避免保留已失效名称筛选。
