# 网页、Android 与 Windows 的坚果云同步（0.8.2）

每个账号的本地业务数据保存在 SQLite。坚果云传输的是压缩增量和快照，不是持续改写中的数据库文件。并发规则、长期数据限制和升级细节见 [六设备同步说明](sync-v2.md)。

## 首次设置

1. 建议全部电脑和手机升级至 0.8.2。Android 使用原签名覆盖安装，不卸载旧数据。
2. 在坚果云账户安全设置中创建第三方应用密码。需要坚果云登录邮箱和此应用密码，不使用网页登录密码。
3. 在所选本地账号的“设置 → 坚果云同步”中启用同步，填写邮箱、应用密码及目录，保存设置。目录只接受 1–60 位字母、数字、下划线或短横线。
4. 同一份数据在六台设备上使用相同的坚果云用户名和目录，例如 GxTodo。不同本地账号使用不同目录；对应关系见 [多账号说明](accounts.md)。
5. 点击“立即同步”，按界面提示接续到完成。首次会创建目录并发布 v2/manifest.json、压缩批次及快照；已有旧版 state.json 会先留存备份，再写入阻止旧版覆盖的升级标记。
6. 在一台设备增加合成任务，其他设备同步确认；反向修改再检查。首次会合并现有内容；全新 0.8.2 数据目录没有演示任务，升级不会自动删除已有条目。

服务地址固定为 https://dav.jianguoyun.com/dav/ 。各设备可以使用该坚果云账号下不同的应用密码。如果目录创建失败，可检查坚果云权限或手动创建同名目录。不要把活动的 tasks.sqlite 放进坚果云客户端同步文件夹。

## 同步时机与范围

开启自动同步后，打开/回到前台约 2 秒后检查；前台空闲约 5 分钟检查一次并有少量随机间隔。保存后约 15 秒合并上传，并尊重可撤销操作的反悔时间。未保存的草稿需先保存或关闭。离线或进入后台暂停，失败会逐步退避，最长约 30 分钟。

Android 没有云同步常驻服务，后台期间收到的新数据在回到前台联网后补齐。系统任务提醒独立使用闹钟，不要求保持前台。每回合有批次数限制；“仍需继续同步”表示尚未处理完，不是丢失数据。

同步内容包括任务、子任务、完成状态、重复与提醒规则、复盘与分值、便签、项目、标签和地点。交互设置、权限、已提醒记录及应用密码保留在各设备。

## 多台设备在一个周期内修改

每个设备写独立的不可变批次，每台接收设备分别记录所有来源的连续已读位置。清单用 ETag 条件更新，发生竞争则重读并只合入本设备进度，防止把别人的提交覆盖掉。下载、应用变更和保存进度由事务协调，缺失批次不会被跳过。

不同字段可以合并；同一字段的真正并发版本都保留，在“设置 → 坚果云同步 → 查看并处理同步冲突”明确选择。删除标记阻止离线旧副本自动复活；删除冲突可明确处理。设备时间不直接决定哪一份赢。

“完成”仅表示已处理本次最后观察到的清单。随后发生的写入要等下一次检查；所有设备最终联网并继续同步后才能补齐。不能保证某设备永久离线时仍实时完整。

## 凭据和备份

Windows 用当前用户的 DPAPI 加密配置，Android 用 Keystore 和 AES-GCM。应用密码不进入业务导出文件或云任务文件；新设备需重新填写。不要把密码放进命令参数、测试脚本或测试报告。

修改用户名或云目录会重置该目录的接收进度，将当前保留的记录版本和删除标记重新发布至新范围。关闭“启用坚果云同步”不删除本地或云端任务。删除也会同步，因此云同步不能替代独立备份。

旧 JSON 在升级时保留原样，仅作为升级前备份；之后的新修改保存在 SQLite。JSON 导出用于可读业务备份，完整设备备份要在退出/停止服务后保存整个账号目录及 SQLite 相关文件。不要直接克隆活动数据库给另一台设备作为新设备运行。

## 常见状态

| 状态 | 处理方式 |
| --- | --- |
| 401 | 检查登录邮箱和第三方应用密码，重新保存 |
| 403 | 检查第三方应用密码、目录权限和账号限制 |
| 429 | 等待退避或服务限流恢复，避免连续点击 |
| 同步会话占用 | 等同一数据库的另一窗口同步结束；异常退出租约最多约 2 分钟失效 |
| 缺少可靠 ETag / 数据损坏 | 保留本地数据和发件箱，停止覆盖；检查服务或损坏批次 |
| 507 | 检查坚果云可用空间 |
| 无法连接 | 检查网络、代理和服务状态；恢复后接续 |
| 仍有后续批次 | 继续同步，直至处理完当前观察到的清单 |

## 当前验收范围

81 项自动化测试通过，包含六个独立 SQLite 客户端的并发/交错同步、故障接续、快照、凭据加密和压缩传输；独立 Android 模拟器验证了真实 APK 的数据库和业务流程。真实坚果云六个独立客户端已通过交错写入、强 ETag 条件竞争、冲突解决、快照和空闲 304 检查。真实 Android APK 与六个桌面客户端的双向收发和逐条内容一致也通过。测试主动控制请求频率，未测套餐的限流上限。未进行六台实体设备长期耗电测试。复用验收流程见 [Android 测试指南](android-testing.md)。
