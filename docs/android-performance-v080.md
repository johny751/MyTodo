三次连接复用的无变化检查都是 **760 字节**；应用重启后的首次无变化检查为 **9,623 字节（9.40 KiB）**，本次连接握手等开销计入其中。三次单条标题修改平均 **5,536.7 字节（5.407 KiB）**，范围 5,536–5,537 字节。全部试验结束时 UI 显示已补齐、outbox 为 0；另从云端读取了 Android 最新批次，确认其中确实有 Perf-edit-3。

热连接试验间隔较短；前台默认五分钟间隔时连接可能已失效，不能假定每次自动检查永远只有 760 字节。第一次 UI 判定脚本用了错误的完成文案，该次用作预热并排除，表中从修正后的完整试验开始。


后台窗口并非零流量：接收 1,123 字节、发送 18,479 字节，合计 19,602 字节。窗口前后 APP 均未处于前台，自动同步保持开启。采样后观察到属于应用 UID 的 HTTPS 待连接 / SYN_SENT 套接字，其中有 172.217.115.4:443；它与当时坚果云 DNS 返回地址不同，随后这些待连接消失。现有证据没有逐请求归因，不能把全部字节断言为数据同步，也不能简单归为连接收尾。后续 60.07 秒窗口仍有 4,380 字节。恢复前台时第一份 UI 仍显示入后台前的 17:43 同步状态；这不是逐请求追踪，不能单凭文案证明没有任何请求。当前只能报告应用 UID 总网络用量，后续需要网络追踪或受控真机对照才能确定来源。

这些是特定场景的小样本。内存端点不是整个窗口的峰值；没有覆盖搜索、导入、大快照和异常网络的峰值。不能据此承诺十万条数据或所有低端手机的性能。

## 统计方法和含义

### 内存与 CPU

[采样工具](../scripts/android-profile.mjs)先核对 AVD 名称和 root 权限，从进程表找到本包进程，再从 Android 活动服务的绑定关系找到属于本 APP 的 WebView renderer。不能把系统所有 WebView 进程都加进来，也不能只测包名后声称是完整应用内存。

每个进程使用 dumpsys meminfo --local PID。PSS 按比例分摊共享页；合计 PSS 比直接相加 RSS 更适合描述进程组物理内存负担。原始记录同时保留各进程 RSS、SwapPss，但不把 RSS 之和当成独占内存。不包含整个 Android 系统、宿主模拟器、共享 WebView zygote 或图形服务的所有开销。

CPU 由 /proc/PID/stat 中 utime+stime 前后差值计算；CLK_TCK 来自 getconf，本镜像为 100，计量步长为 10 ms。实际窗口时长来自 /proc/uptime，包含少量 ADB 采样延迟。百分比为“进程组累计 CPU 秒数 ÷ 窗口秒数 × 100”，以一个 CPU 核为分母；100% 代表一个核持续工作。它不是主机任务管理器百分比，也不是耗电百分比。值为 0 时只表示该窗口在计量分辨率内未观察到累计增长。

定时窗口内不触摸、不截图、不读取 UI。窗口开始前与结束后采内存；前后 PID 及进程启动时间必须一致，否则整份样本无效。ADB 和系统诊断本身会带来扰动，所以结果仍是带测量工具的观察值。

### 真实同步流量

读取 dumpsys netstats 中实时 BPF mAppUidStatsMap，按应用 UID 及归属 renderer UID 取差值，保留接收/发送字节与包数。它统计应用 UID 的内核网络用量，包含实际 HTTPS/TLS 和协议开销，不等于只有 gzip 业务载荷的长度；不包含所有共享系统服务或 Wi-Fi / 蜂窝链路层计费开销，也不承诺等于运营商账单。

手动同步按“操作前计数 → 点击立即同步 → UI 显示完成且 outbox=0 → 操作后计数”测量。没有改动时只做条件清单检查；编辑试验只改一条合成任务的标题，待编辑真正落盘后开始计量。UI 检查会影响观察到的耗时，因此这里的耗时是操作验证窗口，不能当作精确 HTTP 请求延迟。

连接是否复用、TLS 会话、网络重传、服务端响应、并发竞争和远端新增记录会改变字节数。首次全量同步、快照和长期积压需要单独测量，不能把单条修改乘以记录数预测所有场景。

此前桌面基准的“一个字段事件 241 字节 JSON / 200 字节 gzip”只是示例载荷大小，不是 Android 实际网络流量，不能直接拿来计算月流量。

## 电池：当前没有真实能耗测量

本次没有实体手机电流/电压记录，也没有可用的 mAh、mWh 或每小时电量下降数据。模拟器的电池百分比是虚拟状态，不能用于计算真实续航。CPU 时间和后台网络字节只能说明工作量，不能转换为可靠的耗电百分比。

代码策略为前台空闲约 5 分钟检查、编辑后约 15 秒合并、后台/离线暂停、失败退避，不使用同步常驻服务或同步唤醒闹钟。系统提醒是另一条业务路径；本报告没有覆盖到期提醒、桌面小组件频繁刷新等工作量。一次短时后台样本只能支持该窗口的观察，不能证明一夜或所有品牌手机永远零耗电。

### 真机补测方案

至少选主力手机和一台低内存手机，记录机型、Android/WebView 版本、电池健康、网络类型、亮度、温度及同一 APK 哈希。使用独立合成账号，分别测试 21 条、5,000 条以及预期长期数据量。

1. 做对照：相同亮度、网络和初始电量区间，分别测“同步关闭”和“同步开启”。前台静置、每分钟一次编辑、熄屏后台各自成组；Wi-Fi 与蜂窝分开。
2. 前台每组至少 30 分钟，熄屏每组至少 8 小时，各重复 3 次，交换执行顺序。采集系统电池统计、UID 流量、CPU/唤醒活动以及测试前后电量，保持其他应用工作负载尽量一致。
3. 优先使用支持该机型的电源测量仪或可信电池电流/电压记录积分求 mWh。Android 系统按 UID 的能耗可能是功耗模型估计，应标为“系统估计”。无法可靠归属时报告整机差值，不冒称为应用独占能耗。
4. 使用 battery historian / bugreport 排查唤醒锁、闹钟及后台执行；bugreport 可能包含私人信息，分享前检查。在专用测试手机中才考虑重置 batterystats，避免清掉日常手机的已有统计。
5. 实际电池试验应拔掉充电线，使用无线 ADB 或预先安排好采样；USB 充电状态下不能用电池下降量代表正常使用。不要把 dumpsys battery unplug 模拟成已物理断电。
6. 同时验证来电、断网重连、系统省电模式、后台被回收后重开仍能补齐，分别记录功能正确性和能耗。

报告每组平均值、范围及样本数；电量百分比过粗或噪声大于差值时，应写“未能分辨差异”，而非零耗电。

## 复现命令

先按 [独立 Android 测试指南](android-testing.md)启动专用 AVD、安装同一 APK、准备同样场景。以下命令在项目根目录的持久 PowerShell 终端运行，SDK 路径按本机替换。复现单条修改 / 后台场景时，启动命令加 --vulkan off，例如 `node scripts/android-qa.mjs start --avd-home <专用目录> --vulkan off`；这会传给模拟器 -feature -Vulkan。不要并行启动同一 AVD。

~~~powershell
$env:ANDROID_HOME = 'C:/Your/Android/Sdk'
$adb = "$env:ANDROID_HOME/platform-tools/adb.exe"
& $adb -s emulator-5580 root
node scripts/android-profile.mjs snapshot --out qa-evidence/snapshot.json
node scripts/android-profile.mjs sample --seconds 60 --label foreground-idle --out qa-evidence/foreground-1.json
node scripts/android-profile.mjs sample --seconds 60 --label foreground-idle --out qa-evidence/foreground-2.json
~~~

后台试验要先在 APP 内开启自动同步并等待本轮结束，再按 Home；不能用 force-stop 代替后台。确认已经离开 APP 后，在另一个终端启动采样。若要复现本文跨过默认五分钟检查周期的窗口：

~~~powershell
& $adb -s emulator-5580 shell input keyevent 3
node scripts/android-profile.mjs sample --seconds 360 --label background-auto-sync --out qa-evidence/background.json
~~~

每次使用新输出路径，工具拒绝覆盖证据。工具只用于支持 adb root 的专用调试模拟器，且拒绝 emulator-5554；不要求给实体手机 root。根权限不足、BPF 格式不匹配、renderer 无法归属、PID 更换、计数归零或设备消失都会失败，应保留失败原因重新采样，不能补写零。

## 排除的失败样本与限制

- 调试阶段直接对 WebView renderer 执行普通 dumpsys meminfo，触发了渲染进程诊断回调崩溃，随后应用结束。堆栈指向 dumpMemInfo / FastPrintWriter 等诊断路径。本报告改用 --local；此前失败过程不纳入数值统计，也不将它当作普通静置场景的崩溃证据。
- 第一轮定时样本中专用模拟器退出，出现 device not found，未形成完整样本。之后得到两轮完整前台样本；独立宿主进程又在样本结束后以 0xC0000005（访问冲突）退出。随后禁用 Vulkan 继续测试。这是宿主模拟器故障，尚不能确定根因；不会把任何失败窗口报告成 CPU / 流量为零。
- 目前前端仍载入完整业务投影，SQLite 并未消除全部 JavaScript 状态和桥接开销。进一步降低大量历史数据内存，应优先改为 SQL 分页和按需查询。
- 真机功耗、蜂窝弱网、批量导入/首次同步峰值、六台实体设备的长期运行未测。本次结果不覆盖这些能力。
